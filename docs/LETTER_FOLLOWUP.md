# 手紙お届け後の電話台本

企業を開き「トークスクリプト」を選ぶと、保存した手紙に対応する台本を確認できます。「手紙」画面と「電話」画面にも入口があります。

## 使い方

1. 元の手紙を共有保存する。
2. 「手紙から台本を作る・作り直す」を開き、関心・質問・手紙の根拠となる一節・費用条件を確認して下書き保存する。
3. 元の手紙と台本を読み比べ、内容確認を保存する。無料撮影の条件を含む台本は管理者が確認する。
4. 実際に届けた後に、その本文の版・日付・方法・届けた人を記録する。受付への預け入れと、本人の受領・閲覧は別。
5. 「セリフを開く」で相手の返答ごとにボタンを選ぶ。電話後、実際の結果を既存の電話結果画面へ記録する。

台本の生成・閲覧・分岐ボタンでは、お届け・架電・予約実績は増えません。電話前の企業情報・商流・窓口条件は既存の基準に従い確認します。

## 保存領域

すべて既存のsource_data.sales_opsを最新行へマージして保存します。

- letter_versions: 本文、宛名、SHA-256、版ID、保存・取得日時。
- letter_followup: schema_version、active_script_id、scripts。台本は元の手紙のスナップショット、根拠箇所、質問、費用条件、返答別nodes、内容確認のスナップショットを持つ。
- letter_deliveries: 人が入力した実際のお届け。手紙の版・日付・方法・担当・本人へ渡ったかを保持。誤入力は削除せず取消情報を追記。

手紙が編集されても、すでに届けた版と台本は残します。元の手紙や台本の内容が変わった場合は確認し直すため、古い内容確認のスナップショットを流用しません。

## 生成の範囲

アプリ内の下書き作成は、保存済みの手紙の一節を初期値として表示し、担当者が関心と質問を整える方式です。外部AIサービスへの接続や有料API呼び出しは行いません。ChatGPT等の調査作業で個別に作成した台本も、同じ形式で確認待ちとして追記できます。継続自動生成のスケジュール変更は、この実装には含めません。

既存のリーフレット用ガイドとcall_scriptは保持します。画面のトークスクリプトタブから、手紙用・リーフレット用を明示的に選べます。

## 検証

node --test tests/letter-followup.test.cjs tests/ui-integration.test.cjs

手紙の版、営業実績の不変性、根拠の照合、無料撮影条件、拒否時の終了、受取人別の冒頭、旧版保持、営業停止、企業切替、保存失敗を検証します。UI統合テストはDOMアダプターで画面処理と保存処理を検証するもので、実ブラウザーの見た目の検証とは別です。

## 2026-10-16 操作の簡略化
会社のトークスクリプトを開くと、すぐ最初のセリフと相手の返答ボタンを表示する。台本作成フォーム・内容確認・お届け記録は閲覧の前提にしない。既存の会社別台本があればその関心・質問を使い、未作成でも保存本文の抜粋に基づく台本を自動表示する。実績や承認は自動追加しない。お届け記録がない場合も自然な「したためたお手紙の件」という冒頭とし、届いた・読んだとは断定しない。詳細な記録や手動調整は折りたたみへ移す。返答ボタンは今は考えていない・インタビューが苦手・費用・社長へ伝えるを含む。会話継続時の撮影なし面会、担当者への面会、許可を得た再連絡を案内し、明確な拒否は終了する。

## 2026-10-16 前平本人の対話と次の接点

手紙後は、手紙を書いて届けた前平雄一朗自身が電話する台本。受付で映像の説明から始めず、感銘を受けた歩みについて直接伺いたい動機を短く示し、代表者への取次ぎをお願いする。制作の仕事は隠さず、面会・撮影・制作契約を分ける。会社別の既存interest/question/evidenceは保持し、表示時の分岐テンプレートを更新する。

- 「今回は結構」→今回は面会を見送り。資料送付の可否を一度だけ伺う。
- 「今後も連絡不要」→終了。全営業停止は実際の電話結果を保存したときのみ設定。
- 「資料だけ・電話不要」→資料送付了承と電話不要を分けて保存。phone_usable=falseと理由を残し、全媒体禁止へ拡張しない。
- 「数か月後なら」→相手が選んだ3/6/12か月または指定日時を、次回対応として保存。ボタン操作だけでは実績を作らない。
- 資料送付了承と再連絡了承は独立したチェック。資料を依頼されたことを、再電話・面会承諾と扱わない。

電話台本の最上部に「通常の電話・DM後」「手紙を届けた後」の大きな切替を固定。本文24〜26px、反応ボタン64px以上。スマホは反応ボタンを一列に配置。補足・根拠・調整は折りたたみ。会社別台本の閲覧前に入力や承認保存は不要。

新しい電話結果：not_now / followup_allowed / material_requested / material_only。従来declinedの意味は明示された営業停止のまま維持し、古い履歴を書き換えない。この実装・デプロイではDBの営業実績・担当・企業情報は変更しない。資料メールの送信や自動予約も行わない。

`letter-followup-preview.html` は架空企業のみの表示確認用。実データやキーを含まず、保存や外部送信を行わない。
